STUDY-MATE-SKILL · 工作流与架构

一个 SKILL.md 怎样驱动一整套自学系统

这份教程拆解 E:\Code\Study-Mate-Skill：它装进 Claude Code 之后，AI 怎样被触发、怎样当好「总控」、怎样把活派给 5 个子代理，以及磁盘上每个文件由谁写、被谁读。所有带 ↗ 的文件名和流程图方框都能点开，点开后逐行显示该文件的原文，并定位到相关段落。

0. 一页看懂

它是什么

一个编排型技能：SKILL.md 本身不教知识，只规定流程。AI 读了它之后扮演「总控」，负责定流程、和学生对话、记档案，把检索、写课件、出题这些重活派给子代理。

为什么能跨会话

学习状态全部写在文件里（MEMORY.md、progress.yaml……）。每次开场按「恢复视图」只切片读取相关部分，所以上下文一直很短，下次会话也能从上次停下的地方接着学。

为什么质量可控

模型一个字 HTML 都不写：讲解角色写内容 .md，出题角色写 .quiz.json，页面由 Python 渲染器一次生成，再过 4 道带行号报错的确定性校验。

1. 装进 Claude Code

README 的做法是把整个目录复制到宿主的技能目录（README · 安装）。要注意一点：技能名以 frontmatter 的 name: study-mate-skill 为准，把目录名也改成一样，/study-mate-skill 的触发名和目录才对得上。在 PowerShell 里：

Copy-Item -Recurse E:\Code\Study-Mate-Skill "$HOME\.claude\skills\study-mate-skill"
python -m pip install pyyaml jsonschema

装好之后，在任意目录开一个 Claude Code 会话，说一句「我想学 X」或输入 /study-mate-skill 就能触发。学习数据默认写到 <root>/workspace；想换位置，改 studymate.config.yaml，或者设置环境变量 LEARN_WORKSPACE。

2. Claude Code 怎么加载它：三层渐进式披露

Claude Code 不会把整个技能包一次性塞进上下文，而是分三层、按需加载。StudyMate 在第三层又加了一条硬规矩：「需要哪份就读哪份，别一次全读进来」（见 SKILL.md 开头的索引表）。

第 1 层 · 元数据（常驻）

会话启动时，Claude Code 扫描 ~/.claude/skills/*/SKILL.md，只把 frontmatter 里的 name、description、argument-hint 放进技能列表，占用的 token 很少。

description 里写好了触发语：「我想学 X」「继续学 X」「考考我」「这段没看懂」。

第 2 层 · SKILL.md 正文（触发时）

用户的话和 description 匹配上，或者用户手动输入 /study-mate-skill，模型就调用 Skill 工具。Claude Code 把 SKILL.md 正文和它所在目录的绝对路径（Base directory）一起注入上下文，这个路径就是文档里反复出现的 <root>。

第 3 层 · references / scripts（按需）

SKILL.md 开头有一张「什么时候读」的表，总控只在需要时用 Read 读对应的规格。派活时，它只把规格的绝对路径交给子代理，由子代理自己去读。脚本则通过 Bash 执行，脚本源码不进上下文。

图 1　几个关键点：① 开场第一步永远是定位 <root> 和工作区，不在会话 cwd 里读写；② 盘问由总控亲自做，用 AskUserQuestion 一次一张卡片，推荐项放第一个；③ image-scout 和 curriculum-designer 是全流程里唯一允许并行的一段，因为两者不写同一个文件；④ 每轮回复都以「下一步」收尾，这是硬规则。

3.2 图 1-B：学习循环里，一个节点怎样从派工走到呈上页面

对应 SKILL.md §四 学习循环。节点按 kind 分两条路：概念课和实操课串行两段，先由讲解角色写正文和锚点，再由出题人出题；实验课只派出题人，产出实验说明页和验收任务。两条路最后合流，统一经过渲染器和检查。

图 1-B　为什么必须串行：题库和内容文件之间靠 ::: quiz 的锚点文本逐字对位。锚点是讲解的产物，内容文件还没落盘时出题人无从对齐，所以「两边同时开工必然对不上」。报错按归属打回：内容问题退给 learning-coach，题库或锚点问题退给 practice-evaluator，总控不代改。

3.3 图 1-C：总控派一次活的完整往返

对应 SKILL.md §九 角色派发。这张时序图适用于全部 5 个角色。

图 1-C　派工 prompt 只写三样：① 角色规格的绝对路径（「先读它、照它执行」）；② 值（路径、节点 id、载体……），不复述要求和格式；③ 一句三条边界（不自行委派子代理、不直接向用户提问、不建也不改环境）。子代理的长产出不放在回复正文里（回复会被压缩），而是落到 /tmp/<角色>-<id>/deliver/，由总控 cp 原样搬进科目目录。这样一份产物只经过作者一个人的手。

渲染器的铁律是「认不出就报错」：碰到未知指令、锚点缺题又没写 empty_reason、题库里有孤儿键、同一锚点被引用两次、配图文件不存在，都会带 <文件>:<行> 报错，绝不静默降级。所以总控不用手工核对「题目位置 ↔ 题目」，这件事交给检查脚本。

5. 设计原理：为什么这样拆

状态外置，上下文保持很短

聊天式学习的死穴是会话一长上下文就装不下，关掉之后什么都不留。这里把所有状态写成文件，开场只切片读「恢复视图」。

record-keeping · 读写规则

总控和工人分离，只派五类活

判断标准是：这件事需要外部检索、大量生成或独立验证吗？不需要就别派。信息源已经在总控上下文里的活（答疑、盘问、元数据、档案），派出去还得先转述，更慢也更费。

SKILL.md §九 角色派发

传路径，不转述

上游产出只给绝对路径和节点 id，由下游自己去读。转述会失真，还会让总控上下文膨胀：一份题库 15 KB，一套 lab 20 KB，一份大纲 46 KB。

SKILL.md · 交接与返回

模型不写 HTML，页面交给确定性渲染

内容格式只允许一小套块语法，块级 HTML 标签会被拦下。版式统一、可以回归测试，同时把模型最容易出错的部分挪到了代码里。

课件内容格式.md

靠锚点对位，不靠序号

::: quiz 的锚点文本是内容和题库之间唯一的接头。按序号对位，一旦两边不一致就会静默错位；按锚点对位，对不上就直接报错。

课件内容格式.md

一处定义，别处只给指针

课件内核归 lesson-design，题目归 layered-practice，配图归 learning-coach 的「配图」一节，状态读写归 record-keeping。规则不会出现两份，也就不会漂移。

工程约束 §二

证据分级，出题人的防线

出题和批改是同一个角色，所以口头确认单独出现时不足以判过。证据可信度从高到低：运行结果、学生自己写的测试、解释能力、口头确认。

evidence-check

验收不过，退回作者本人

带上失败的原文证据退回，总控不代改，也不另开新角色。这样每份产物只有一个 owner，出了问题能追到人。

6. 在 Windows + Claude Code 上跑的注意事项

实测：这台机器上的 python3 是 Windows 商店的占位别名。执行 python3 -c "print(1)" 没有任何输出，退出码是 49。可 SKILL.md 里所有脚本命令都写的是 python3。可选的处理方法：到「设置 → 应用 → 高级应用设置 → 应用执行别名」里关掉 python3 的别名；或者在 ~/.claude/CLAUDE.md 里写一句「运行 StudyMate 脚本时用 python 代替 python3」。另外 jsonschema 目前没装，缺了它 check_curriculum.py 的 schema 校验会降级成 WARN。
python -m pip install jsonschema
/tmp 暂存路径（可能踩坑）：派工约定把产物落到 /tmp/<角色>-<id>/deliver/。在 Git Bash 里 /tmp 会被映射到一个 Windows 临时目录，cp 能正常工作；但原生 Windows 的 Python 不认识 /tmp/… 这种路径。如果 apply_empty_reasons.py 拿到的 TSV 路径是 /tmp/…，就可能报找不到文件。遇到这种情况，可以先用 cygpath -w 转换路径，或者把暂存根目录换成一个 Windows 绝对路径。
名字对齐：frontmatter 里是 name: study-mate-skill，仓库目录却叫 Study-Mate-Skill。装到 ~/.claude/skills/ 时，建议把目录名也改成 study-mate-skill，这一点 README 里也提到了。
