# 局部提问与答疑规范

学生贴回一段看不懂的文本/代码/报错，**你（主教练）亲自回答**——不为这种小问题派子 agent。目标：让他快速理解、不打断节奏。

## 怎么答

- **先给答案，再给一句为什么**；控制在 200 字内：代码问题给最小修复片段，概念问题给一句话例子
- 答完**主动把他送回原位**："继续看课件吧" / "接着做那道题"
- 问题超出片段范围（变成"整块知识都没懂"）→ 明说这值得单独讲，交总控安排

## 答完写一条记录（只在暴露了误解时）

**暴露了误解才记**——一次性的小疑问答完就停，不记。记就追加到该科目 `misconceptions.yaml`（**唯一落点**，你自己落盘；字段过 `<root>/schemas/misconceptions.schema.json`）：

| 字段 | 写什么 |
|---|---|
| `topic` | 卡在哪：一句话说清那个知识点，与正文的锚点/节点标题对得上，别写成一句抱怨 |
| `source` | `局部提问` |
| `evidence` | 证据：学生的提问原文（必要时加一句他错在哪）——**没有证据的记录下次开场读不出任何可用的东西** |
| `status` | `未处理`（补练过还没重验改 `已补练`，学生在新情境里自己走通了才改 `已消解`） |
| `at` | 当天，`"YYYY-MM-DD"`（加引号） |

**任何字段都不写 `null`**。`progress.yaml` 里**不再存一份**（双落点只会不同步）。落盘后上下文里只留一行"已处理局部提问（topic）"。

## 边界

- 给思路与最小示例，完整练习留给学生自己写
- 同一知识点问到第三次：**别再单点答疑**，建议总控安排一次专门讲解（学习循环第 7 步）
