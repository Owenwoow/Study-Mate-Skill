# 安装、工作区与迁移

本技能包不写任何安装脚本——它就是一个目录，装法只有一步：**放进宿主扫描的技能目录**。

## 一、依赖

| 依赖 | 必需？ | 用来做什么 |
|---|---|---|
| Python 3.9+ | **必需** | 全部脚本（主页生成、课件渲染、四道校验、批处理） |
| `pyyaml` | **必需** | 读 `curriculum.yaml` / `progress.yaml` / 技能 frontmatter |
| `jsonschema` | 建议 | `check_curriculum.py` 的 schema 校验；缺了降级为 `WARN`（只报重复 id、悬空引用、环） |
| `bash` + coreutils | 可选 | `scripts/tests/run_tests.sh` 回归测试 |
| `node` | 可选 | 两套前端 DOM 测试（`quiz_dom_test.js` / `toc_dom_test.js`） |

```bash
python3 -m pip install pyyaml jsonschema
```

**依赖缺了检查会变松**：没有 `pyyaml` 时 `check_lesson.py` 跳过"这课该不该有 lab"的判定（只 `WARN`）；没有 `jsonschema` 时 `check_curriculum.py` 跳过 schema 校验。

## 二、装进宿主

本包遵循 Agent Skills 约定：**一个目录一个 `SKILL.md`**，目录名与 `SKILL.md` 里的 `name` 对应。

| 宿主 | 用户级技能目录 | 项目级技能目录 |
|---|---|---|
| WorkBuddy AI | `~/.workbuddy-ai/skills/` | `<项目>/.workbuddy-ai/skills/` |
| Claude Code | `~/.claude/skills/` | `<项目>/.claude/skills/` |
| 其他宿主 | 按它自己的约定；认「目录 + `SKILL.md`」的都能用 | 同上 |

```bash
# WorkBuddy AI，用户级
cp -r Study-Mate-Skill ~/.workbuddy-ai/skills/

# Claude Code，用户级
cp -r Study-Mate-Skill ~/.claude/skills/
```

**注意**：宿主按**目录名**或 frontmatter 的 `name` 索引技能。本包的 `name: study-mate-skill`。如果你把目录改名（例如改成 `studymate`），把 `SKILL.md` 的 `name` 一起改掉，然后跑一次 `python3 scripts/check_skill.py` 确认——它按「`name` 与目录名（归一化后）一致」校验。

装好后自检：

```bash
python3 ~/.workbuddy-ai/skills/Study-Mate-Skill/scripts/check_skill.py
```

## 三、学习工作区在哪

工作区（记作 `LEARN_WORKSPACE`）**三级定位**，前者优先：

1. **环境变量** `LEARN_WORKSPACE`——宿主或用户显式指定；
2. **`<root>/studymate.config.yaml`** 的 `workspace:` 键——可写相对本包的路径，也可写绝对路径；
3. **`<root>/workspace`**——默认位置，不存在时由 `gen_home.py` 自动创建。

`studymate.config.yaml` 长这样：

```yaml
# 学习工作区定位。相对路径按本包目录（<root>）解析；不写就用 <root>/workspace。
workspace: workspace
```

**为什么要三级**：宿主可能在任意目录启动会话（写代码的项目、临时工作区），学习数据必须集中在一处、由配置定位，而不是散落在会话 cwd 里。总控每次开场先解析这两个绝对路径（`<root>` 与 `LEARN_WORKSPACE`），再开始读状态。

**建目录的规矩**：解析出来的工作区（环境变量 / 配置 / 默认）**不存在时自动创建**——第一次把 `LEARN_WORKSPACE` 指到一个新目录就能直接用；而 `gen_home.py` 的**位置参数**必须是已存在的目录（拼错要报错，不静默新建一个空工作区）。

**换位置**：

```bash
# 方式一：改配置（持久）
# 编辑 studymate.config.yaml → workspace: D:/study

# 方式二：环境变量（临时 / 每次会话）
export LEARN_WORKSPACE=/path/to/study        # Windows PowerShell: $env:LEARN_WORKSPACE='D:\study'
```

## 四、换机器 / 迁移

学习数据全在工作区里，引擎全在包内——**拷走 = 迁移**。

| 场景 | 怎么做 |
|---|---|
| 工作区在包内（默认） | 把**整个技能包**（含 `workspace/`）拷到新机器，放进宿主的技能目录 |
| 工作区在包外 | 包与工作区分别拷；在新机器上把 `studymate.config.yaml` 的 `workspace:` 指向工作区的新位置 |
| 只在同一台机器换工作区 | 改 `studymate.config.yaml` 或设 `LEARN_WORKSPACE`，不用搬文件 |

迁移后跑一次 `python3 scripts/gen_home.py` 刷新主页（顺带把共享前端资源铺到工作区），再跑 `check_skill.py` 确认包完整。

**不进迁移包的东西**：本机工具链（`.venv/`、`node_modules/`）、`.preview/`（预览产物）。学习产物（科目、课件、图片库、档案）**要跟着走**。

## 五、包完整性的自查清单

```bash
cd <root>

python3 scripts/check_skill.py                     # 1. 入口 + 11 份参考规格的 frontmatter
ls references/roles references/protocols           # 2. 5 个角色 + 6 个协议都在
ls schemas/                                        # 3. 5 份 schema
python3 scripts/preview_templates.py               # 4. 模板与前端资源能渲染（.preview/ 是临时产物）

# 5. 用示例科目端到端跑一遍引擎（复制一份再跑，别改原示例）
cp -r examples /tmp/sm-check
python3 scripts/gen_home.py /tmp/sm-check
python3 scripts/check_curriculum.py /tmp/sm-check/.learning/subjects/*/curriculum.yaml
python3 scripts/check_pool.py /tmp/sm-check/.learning/subjects/typescript-web-api
python3 scripts/render_lesson.py /tmp/sm-check/.learning/subjects/typescript-web-api http.basics --check

# 6. 回归测试（自己造临时科目，不碰工作区）
bash scripts/tests/run_tests.sh
```

## 六、要改引擎时

引擎 = 本技能包（`SKILL.md`、`references/`、`scripts/`、`templates/`、`schemas/`）。**学习会话里它是只读的**；改它走版本管理。

改动前后必做：

| 改了什么 | 跑什么 |
|---|---|
| `SKILL.md` 或 `references/roles`、`references/protocols` | `python3 scripts/check_skill.py` |
| `references/课件内容格式.md` | `python3 scripts/tests/test_render_lesson.py`（它断言「渲染器代码 = 该文档 = 测试里写死的集合」三份逐字一致） |
| `templates/` 或 `templates/assets/` | `python3 scripts/preview_templates.py` + `bash scripts/tests/run_tests.sh` |
| 任一 `scripts/*.py` | `bash scripts/tests/run_tests.sh` |

**改共享前端资源要同时改三处**（否则页面会静默少加载一个文件）：`templates/assets/README.md`、`scripts/preview_templates.py` 的 `shared_files`/`shared_dirs`、`scripts/gen_home.py` 的 `ensure_shared_assets`。

**已共享资源更新后要同步到已有科目**：`templates/assets/` 里的 `style.css`、`quiz.js`、`lesson-toc.js` 一改，各科目 `assets/` 里的同名副本就旧了，要一起覆盖（科目自己新增的组件别动）。
